# ローカル運用ツール（あなたのPCで動かす道具）

Claudeが作り、**あなたのPCのローカルLLM（LM Studio）が実行する**ための道具です。
クラウド課金なし・無制限・場中いつでも使えます。

---

## セットアップ（初回だけ・5分）

### 1. LM Studioでサーバーを起動
1. LM Studioを開く
2. 左のアイコンから **Developer（`</>`）** タブを選ぶ
3. **Start Server** を押す（既定は `http://localhost:1234`）
4. モデル（Gemma 4 E4B など）が読み込まれていることを確認

> 💡 **速度改善**: 設定で **Reasoning/Thinking を OFF** にすると3〜5倍速くなります。要約作業に思考モードは不要です。

### 2. Pythonの準備
コマンドプロンプト（スタートメニューで「cmd」と検索）で：
```
pip install requests
```
※Pythonが無い場合は https://www.python.org/downloads/ からインストール（**「Add python.exe to PATH」に必ずチェック**）

### 3. kabu.py を保存
このフォルダの `kabu.py` を、分かりやすい場所（例：`C:\kabu\kabu.py`）に置く。

---

## 使い方

コマンドプロンプトで、置いた場所へ移動してから実行します。
```
cd C:\kabu
```


### まず接続確認（うまくいかない時はこれ）
```
python kabu.py --check
```
- `✅ 接続OK。利用できるモデル: ...` → 準備完了
- `⚠️ モデルが読み込まれていません` → LM Studioで **「+ Load Model」(Ctrl+L)**
- `❌ サーバーに届きません` → Developer タブで **Start Server**

### 開示・決算を解読する（いちばん使う）
```
python kabu.py
```
→ 本文を貼り付け → **Ctrl+Z を押して Enter** → 30秒ほどで解説が出ます

### 決算の「予想比」をチェックする
```
python kabu.py -m b
```
先週のディスコ（4割増益でも予想割れで急落）・信越化学（増配でも計画が予想割れで-6%）の
失敗を繰り返さないためのモードです。

### 材料の質を25点満点で採点する
```
python kabu.py -m c
```

### 用語をその場で調べる
```
python kabu.py -m d -t 逆日歩
```

### ファイルから読み込む
```
python kabu.py -f news.txt
```

## 🔑 EDINET連携（あなたのPCだけの特権）

**EDINET API（金融庁の開示システム）は海外IPを遮断しています。**
クラウドのClaudeからは403で使えませんが、**日本にあるあなたのPCからは使えます。**

### 準備
1. https://api.edinet-fsa.go.jp/ でAPIキーを取得（無料）
2. コマンドプロンプトで環境変数に設定（**そのウィンドウを閉じるまで有効**）：
```
set EDINET_API_KEY=あなたのキー
```
※毎回設定するのが面倒なら、Windowsの「システム環境変数の編集」で恒久設定できます

### 使う
```
python kabu.py --edinet                    # 今日の大量保有報告書を一覧表示
python kabu.py --edinet --analyze          # ＋ローカルLLMが解説
python kabu.py --edinet --date 2026-07-30  # 日付を指定
```

**なぜ重要か**: 大量保有報告書は「誰が・どの銘柄を・何%買ったか」の一次情報です。
アクティビスト（＝物言う株主）の買い増しは、ニュースになる前に分かります。
**朝のレポートより速い情報が、あなたのPCから直接取れます。**

---

## 実戦での動線

```
SBIアプリのアラートが鳴る（+5%上昇 など）
  ↓
株探やSBIで開示・記事を開く → 本文をコピー
  ↓
python kabu.py  → 貼り付け → Ctrl+Z → Enter
  ↓
30秒で「何がすごいか・注意点・予想比は分かるか」を把握
  ↓
朝レポートで決めた鉄則（損切りライン・見送り基準）で判断
```

---

## 困ったとき

| 症状 | 対処 |
|---|---|
| つながらない | LM StudioでStart Serverを押したか確認 |
| 遅い（1分以上） | Reasoning/ThinkingをOFF、Context Lengthを4096に |
| 落ちる | モデルを小さく（8B→4B）、他アプリを閉じる |
| EDINETが403 | APIキーを確認。VPNを使っていればOFFに（海外IP判定される） |
| 日本語が変 | Gemma系かQwen系のモデルに変更 |

---

## 注意

- ローカルLLMは**貼り付けた文章の中身しか知りません**。「今日の株価は？」と聞かないこと（もっともらしい嘘をつきます）
- 出力の数字は**必ず原文で確認**してください
- 本ツールの出力は公開情報の整理であり、投資助言ではありません

# 📡 watch.py — 一次情報リアルタイム監視（ニュースより速い）

企業が出した「原文」を、報道より先につかむための道具です。

## いちばん使う3つ

```
python watch.py                  # 今日のTDnet適時開示を一覧
python watch.py --watch --beep   # 60秒ごとに監視、重要な新着で音が鳴る（場中つけっぱなし）
python watch.py --sources        # 一次情報リンク集（どこを見ればよいか）
```

**表示の見方**
- 🔥 = 株価が動きやすい好材料（上方修正・自社株買い・増配・株式分割・TOB・受注 など）
- ⚠️ = 悪材料（下方修正・減配・特別損失・公募増資 など）
- 🆕 = 前回チェック以降の新着

## 絞り込み・応用

```
python watch.py --hot                    # 重要キーワードだけ表示
python watch.py --filter 上方修正         # 特定の言葉で絞る
python watch.py --analyze                # ローカルLLMが「なぜ株価に効くか」を解説
python watch.py --date 2026-08-05        # 過去日を指定
python watch.py --edinet                 # EDINET大量保有報告書（要APIキー）
python watch.py --debug                  # 表示が変な時：HTMLを保存して原因調査
```

## おすすめの使い方（1日の流れ）

| 時刻 | すること |
|---|---|
| 8:50 | `python watch.py` で寄り前の開示をチェック |
| 場中 | `python watch.py --watch --beep` をつけっぱなし。音が鳴ったら画面を見る |
| **15:00〜16:00** | **決算・開示のラッシュ。ここが最も価値が高い時間帯** |
| 材料発見時 | PDFを開いて原文コピー → `python kabu.py -m b` で**予想比を必ず確認** |

## 注意

- TDnetのページ構造が変わると表示が崩れることがあります。その場合は `--debug` を付けて実行し、
  保存された `tdnet_debug_p1.html` をClaudeに共有してください（すぐ直します）
- 監視間隔は既定60秒。短くしすぎるとサイトに負荷をかけるので `--interval 30` 未満は避けてください
- 開示の**PDF原文を必ず確認**してください。タイトルだけでは判断できません

# 🗃️ collect.py — 開示の自動収集（Pythonだけ・AI不要）

**LM Studioを起動しなくても動きます。**メモリ数十MBなのでPCは重くなりません。
「集める」のに知能は不要——AIは後で「読む」ときだけ使えば十分です。

## 使い方

```
python collect.py                 # 30分ごとに自動収集（Ctrl+Cで停止）
python collect.py --once          # 1回だけ（タスクスケジューラ向け）
python collect.py --pdf           # 重要な開示のPDFも自動保存
python collect.py --report        # 今日集めた分の要約を表示
python collect.py --interval 900  # 15分ごとにする
```

## 何が保存されるか

| ファイル | 内容 |
|---|---|
| `data/tdnet_YYYYMMDD.csv` | その日の全開示（**Excelでそのまま開けます**） |
| `data/important.csv` | **好材料・悪材料だけを日付をまたいで蓄積** |
| `pdf/` | `--pdf` 指定時のPDF（重要な開示のみ） |
| `collect.log` | 実行の記録 |

CSVには「区分」列が付きます：**好材料 / 悪材料 / 決算 / 定例 / その他**
→ Excelでフィルタすれば、後から「上方修正だけ」を一覧できます。

**同じ開示は二重に記録されません**（時刻・コード・表題で判定）。
つけっぱなしでも、何度実行してもCSVは汚れません。

## Windowsで自動起動する（タスクスケジューラ）

朝つけ忘れても勝手に動くようにする方法です。

1. スタートメニューで「**タスク スケジューラ**」を検索して開く
2. 右の「**基本タスクの作成**」→ 名前:「株の開示収集」
3. トリガー：「**毎日**」→ 開始時刻 **8:50**
4. 操作：「**プログラムの開始**」
   - プログラム: `python`
   - 引数の追加: `collect.py --once --pdf`
   - **開始（オプション）**: `C:\kabu` ← ここを忘れると動きません
5. 完了後、作成したタスクを右クリック →「プロパティ」→「**トリガー**」タブ
   → 編集 →「**繰り返し間隔: 30分**」「継続時間: 8時間」にチェック

これで **8:50〜16:50 の間、30分ごとに勝手に収集**されます。

## 1日の流れ（LLMを使わない軽量版）

| 時刻 | すること | 負荷 |
|---|---|---|
| 8:50〜16:50 | `collect.py` が自動で収集（またはタスクスケジューラ） | 軽い |
| 昼休み・夕方 | `python collect.py --report` で重要な開示だけ確認 | 軽い |
| 気になる開示があった時**だけ** | LM Studioを起動 → `kabu.py -m b` で予想比チェック | 重い（都度） |

**LM Studioは常時起動しない。これでPCは軽いままです。**
